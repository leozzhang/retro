# Saturday Gridiron

A PC football game inspired by Retro Bowl, set in FBS college football, with more realism: real teams and conferences, deeper playbooks, defensive schemes, and reading the defense. It's a personal project. Current status and the roadmap are in [docs/PROGRESS.md](docs/PROGRESS.md); read it first. The transfer portal, the first offseason system, is in [docs/PORTAL.md](docs/PORTAL.md).

## Stack
- TypeScript, HTML5 Canvas 2D, and Vite. No framework or game engine.
- Vitest for tests. The pixel font comes from `@fontsource/press-start-2p`.
- The desktop app is Electron (`electron/`: the main process and a preload that gives the game file storage for saves). The browser build still runs on its own.

## Run
```
npm run dev         # http://localhost:5173
npm run typecheck   # tsc --noEmit
npm test            # unit tests (src/logic.test.ts)
npm run balance     # headless AI balance report -> balance.txt (BAL_ONLY=id,kind limits the per-play rows)
npm run ratings     # what each rating is worth per position -> ratings.txt (~10 min; RAT_ONLY=QB,WR limits groups)
npm run season      # headless full-season sims -> season.txt (SEASONS=n, default 5)
npm run runfit      # who stops each run, short yardage, and what each block is worth (ablations) -> runfit.txt (~10 s; RUNFIT_ONLY=id,..., RUNFIT_REPS, RUNFIT_CALLS); see docs/RUNGAME.md
npm run trace       # one snap step by step: assignments, positions, blocks (TRACE_PLAY=id TRACE_CALL=id); see docs/FILM.md
npm run film        # every play vs every defensive call -> film.txt + film.json (~2 min; FILM_ONLY=id,kind, FILM_REPS=n, FILM_EXPLAIN=id,..., FILM_BASE=film.base.json); see docs/FILM.md
npm run app         # the desktop app on the Vite dev server (hot reload); `-- --remote-debugging-port=9222` for CDP
npm run app:build   # release/: portable .exe, installer, and win-unpacked/ (the folder Steam would take)
python scripts/build_profiles.py   # rebuild src/data/fbs/profiles.ts from docs/research/profiles_*.json
python scripts/build_history.py    # rebuild src/data/fbs/history.ts from docs/research/history_*.json
```
Controls are listed in [README.md](README.md).

## Conventions
- **World units are yards.** x runs 0–120 along the field: 0–10 is the user's end zone and 110–120 is the opponent's. The user always attacks toward +x. y runs 0–53.3 across the field, with 0 at the far (top) sideline.
- **Rendering is in 640x360 view pixels;** the canvas holds `RENDER_SCALE` (2) device pixels for each, so fine detail can use half pixels (the office's `FINE` pass). Mouse coordinates are view pixels.
- **Fixed 60 Hz timestep.** Each step, AI and user input set `player.want` (desired velocity), then `stepPlayer` accelerates toward it. Don't move players' positions directly; the exception is blockers anchored during an engagement.
- **Separate data, sim and render.** Plays, routes and defensive calls are plain data in `data/`. Sim code never touches the DOM, so the balance harness can run it headlessly.
- **Every rating must change something on the field.** Don't add a rating without the mechanic that reads it. Overall formulas (`OVR_WEIGHTS`) only weight ratings that matter at that position; check with `npm run ratings`.
- **Team ratings are computed, never stored:** `teamRatings(squad)` from the healthy starters. The same goes for season records, standings, stats and award races (from game results), and season rosters (generated roster plus `teamState`).
- **Season state is plain JSON** and season randomness comes from `seasonRng(state, ...)`, so a saved season continues identically.
- **Art is original pixel art drawn in code** (`render/sprites.ts`). Don't copy Retro Bowl assets.
- **Tuning constants sit next to their logic:**

  - `catchOdds`, and the set-receiver bonus `SET_HANDS`, `SET_CONTEST`, readiness and hot balls `READY`, the lob's jump ball `JUMP`, crowds at the catch `CROWD`, ball placement and dives `PLACEMENT` (`sim/catching.ts`)
  - out of the catch: the hip turn and ramp `CATCH` (`sim/player.ts`); defenders on the ball `CATCH_PURSUIT`, who breaks on a throw `BREAK_ON`, the diving tackle `DIVE_TACKLE`, tackling at the catch `AT_CATCH` (`game/playState.ts`); open-field angles `OPEN_FIELD`, routes in bounds `ROUTE_SIDELINE` (`sim/ai.ts`)

- **After changing the season sim, polls, progression, injuries, confidence, morale, departures or recruiting,** run `npm run season` and compare against the flags in SEASON.md, the per-position growth table in PROGRESSION.md (the report flags any position more than 15% off the mean), the injury targets in INJURIES.md (`INJURIES=light` checks the light setting), the confidence targets and farming check in CONFIDENCE.md, and the morale targets in MORALE.md (spread, unhappy players spread across teams, no tracking with confidence), the emphasis targets in COACHES.md, the PORTAL section against PORTAL.md (entrants a team, flows, starter talent by tier against the control), the STAFF section against COACHES.md (head coach changes 15–30 a year, assistant turnover 20%+, talent flowing up, the league level within 2.5 and the T1–T5 staff gap within 1.5 over 5 seasons), the CAREERS section against CAREERS.md (size per season; the rest of the report must not change, since careers are history only), the DEPARTURES section against RECRUITING.md (early entrants, picks by conference, the class ladder, and starter overall by tier since the start), the PARTIAL SIM section against SIMULATION.md (shown, not tuned), the GAME PAGES section against GAMES.md (player-of-the-game shares, no game's scoring plays off its final, the plays' save size), and the OFFICE section against OFFICE.md (story items a few times a decade, none never), the RECRUITING section against RECRUITING.md (signees by tier against their generated-freshman level, the commit pace, early signing, decommits, time per week).
- **After adding or changing plays,** run `npm test` (src/playbook.test.ts holds every play's tags to its data and every style book to the book rules), then `npm run film` and read SITUATIONS first (each play against the looks it beats vs. the looks that stop it; FLAT rows don't care what the defense shows), then FLAGS, TAG MISS and STOP MISS, BOOKS and ROUTES, with `FILM_EXPLAIN` on anything flagged (runs: `npm run runfit`, `npm run trace`), before balancing by hand. Fix mechanics, not single plays. Every new play is tagged and in a style book, and every new concept has its `STOPS` (docs/PLAYBOOKS.md, "Balancing").
- **After changing AI or gameplay,** run `npm run balance` and compare against the baseline in PROGRESS.md and the real-world targets in [docs/TARGETS.md](docs/TARGETS.md) (FBS rushing, including the GAP rows against the talent-gap table, NFL route shapes, splits and completion rates), and the DEF and ADAPT rows against [docs/DEFENSE.md](docs/DEFENSE.md) (a spammed run loses 40%+, a balanced offense little, the counter pays), and the THROW rows against [docs/PASSING.md](docs/PASSING.md) (no throw type best everywhere; early throws to a receiver who isn't looking cost). Check the RUNFIT and ABLATE rows against [docs/RUNGAME.md](docs/RUNGAME.md) (stuffs 15–22%, a backside block worth 1+ yd a carry). Check the POCKET and STUNT rows against [docs/PROTECTION.md](docs/PROTECTION.md) (a connected cup, tackles winning 85–95% at 2.5 s, pressure about 2.9–3.1 s, sacks before 3.2 s unchanged, games no stronger than a straight rush). Flag plays or calls that look overpowered or useless instead of quietly tuning them. A zero lean and no tags must leave the core rows byte-identical.
- **Browser debugging:** in dev builds, `window.game` exposes the `Game` instance, and F1 toggles the debug overlay.
